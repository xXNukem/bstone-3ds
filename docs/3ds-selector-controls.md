# Startup display correction and additional controls

## Distorted game selector

The installed SDL2 N3DS video backend calls
`gfxInit(GSP_RGBA8_OES, GSP_RGBA8_OES, false)`. Citro2D's
`C2D_CreateScreenTarget` configures RGB8 display transfers (output flags 0x1000
in the installed library). Before this correction the shared display owner set
only the bottom framebuffer to BGR8. The top remained RGBA8 throughout the game
selector; `SwVideo::present` set it to BGR8 only after starting the selected game.
That mismatched the bytes per pixel of transfers and display scanout at startup.

The shared owner now sets **both** screen formats to `GSP_BGR8_OES` before target
creation or any frame transfer. The late, redundant `SwVideo` format flag/change
is removed. SDL still owns gfx/HID initialization and shutdown. No SDL windows,
second renderer, gfxInit/gfxExit or stereo projection changes are introduced.
The display lifecycle test rejects target creation unless both formats are
already correct. Actual recovery from the reported distortion needs hardware
confirmation; a host mock cannot validate physical scanout.

## Control schemes

Archived IDs are stable: `0 CLASSIC`, `1 MODERN`, `2 MODERN + C-STICK`.
The existing archived `in_3ds_control_scheme` preference now accepts these three
values, default 0, saved/read through the existing per-game config system.
CONTROL SETTINGS cycles the scheme with one confirmed press. The second row
opens a guide for the selected layout; Instructions uses that same guide.

Classic's button table and original movement path are unchanged. Modern maps:

- Circle Pad: proportional forward/back and strafe left/right.
- A / Y: turn right / left.
- B: interact, including the original PS use/detonator interaction.
- R: fire.
- Physical D-Pad right / left: next / previous weapon, once per press.
- X: existing automap action. START: pause. START+SELECT: existing exit chord.
- Modern + C-Stick adds proportional horizontal turning with the C-Stick;
  A/Y remain available. Vertical C-Stick movement does not introduce freelook.

All menus/intro screens retain the Classic mapping plus their existing direct
A-confirm/B-back handling. Switching mapping context clears keys generated by
the previous layout, preventing retained fire/turn/weapon actions. Changing the
stored scheme also clears keyboard state. Modern uses KEY_DLEFT/KEY_DRIGHT for
weapons, not composite KEY_LEFT/KEY_RIGHT (which include Circle Pad directions).

Analog sampling reuses SDL/libctru's existing HID/IRRST ownership and scans.
Circle Pad deadzone is 20/156 per axis; C-Stick horizontal deadzone is 15/156.
The remaining range maps linearly to [-1000,1000], saturating at full travel.
Forward/strafe diagonals are normalized to avoid a faster maximum diagonal
speed. The original movement tick count and Always Run speed determine the
final deltas in `PollKeyboardMove`. Combined C-Stick and A/Y turning is capped
at the original maximum turn rate. No combat, raycaster, eye math or bobbing
changes; the existing control/demo recording path still receives final deltas.

The third scheme is a conservative interpretation of the requested additional
New 3DS C-Stick control: it shares Modern's button table instead of duplicating
the full input system. Physical feel/sensitivity remains a hardware decision.

## Verification and changed files

`tests/3ds_modern_controls.py` executes production layouts, analog sampling,
scheme getters/setters and `PollKeyboardMove` with mocked HID/cvar storage. It
checks 130,321 stick coordinates, drift, diagonal/speed/tick limits, held weapon
selection, menu context changes, C-Stick direction and return to Classic.
The production archived cvar declaration and per-game persistence infrastructure
are retained; this host test does not claim to test physical input or SD writes.

Existing Classic input (2,048 combinations), menu-switch, terminal, selector,
shared graphics lifecycle and original-weapon stereo/bob tests remain relevant.
The installed devkitARM toolchain produces a stable build with AI weapons OFF.

Files: `bstone_3ds_display.cpp`, `bstone_sw_video.cpp`, `id_in.h/.cpp`,
`3d_play.cpp`, `3d_menu.cpp`, README, initial-candidate notes, display/Classic
regression tests, this document and the new Modern regression test.

Hardware checks: selector top/bottom scanout in 2D/3D; held A/B while entering
menus; all three schemes and config restoration after restart; proportional
Circle Pad diagonals; C-Stick drift, sensitivity and release; all weapons and PS
interaction; unchanged menu navigation and Classic movement.
